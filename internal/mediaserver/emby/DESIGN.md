# Emby HTTP 客户端设计

## 目标与非目标

目标是提供首版实际需要的少量强类型 Emby API，并对并发、连接、响应体、重试、重定向和错误泄漏设置硬上限。

本包不判断订阅是否完成，不轮询媒体库，不保存服务器配置，也不返回 V2 API 响应。

## 请求链路

```mermaid
flowchart LR
    A["调用方 Context"] --> G["每客户端并发槽"]
    G --> T["受限 Transport"]
    T --> R["同源重定向检查"]
    R --> B["解压后响应体上限"]
    B --> D["强类型 JSON DTO"]
```

## 重试语义

- GET 可对临时网络错误、429、502、503、504 做最多 3 次有界尝试。
- `Retry-After` 支持秒数和 HTTP 日期，但等待受调用 Context 与总预算约束。
- 401、403、404、其他 4xx、无效 JSON和超大响应不重试。
- 刷新 POST 不在客户端自动重试。超时或 EOF 可能表示服务端已经接收请求，因此返回 `outcome_unknown`，由上层先确认再决定后续动作。

## 安全决策

| 决策 | 理由 |
| --- | --- |
| Token 只放 `X-Emby-Token` | 避免凭据进入 URL、代理访问日志和浏览历史 |
| Base URL 拒绝 userinfo/query/fragment | 防止隐式凭据和端点参数污染 |
| 重定向仅同源且禁止 HTTPS 降级 | 防止 Token 被带到非预期主机或明文链路 |
| 限制解压后响应 | 防止 gzip 炸弹绕过线上的 Content-Length |
| 错误正文截断并脱敏 | 防止 HTML 错误页、路径或密钥进入日志 |

## 资源边界

- 每客户端最多 4 个在途请求。
- 每主机最多 4 个连接，空闲连接可回收。
- Items 查询单页 `Limit` 最大为 200，`StartIndex` 最大为 10000；媒体唯一确认使用 `Limit=2`，剧集枚举使用有界分页。
- 错误响应最多读取 64 KiB；成功响应按端点设置上限。

## 已知限制

- 首版不实现用户、会话、实时播放状态或完整 Emby OpenAPI。
- `latest`、`playing` 等 V2 能力在上层暂以兼容空状态返回。
- 媒体唯一确认、路径风格和 Provider ID 交叉校验位于 `internal/mediaindex` 与应用适配层。

## 备选方案

- 未为唯一确认和剧集枚举建立两套 HTTP 客户端，因为两者共享鉴权、重试、重定向和响应体边界；调用方通过不同的显式分页上限表达语义。
- 未提供无上限自动翻页方法，因为调用方必须决定总结果预算、去重规则和超过预算时的失败语义。
