# siteflow 设计

## 设计目标

唯一行为基准是 MoviePilot V2 `2.15.6`。本包隔离“站点快照已经保存”之后的业务副作用，使 HTTP 兼容层不直接承担历史持久化和通知投递。

非目标包括站点解析、快照写入、通知模板渲染、增加通知渠道、引入 River 持久重试，以及修复 V2 已有怪癖。

## 数据流

```text
HTTP 刷新成功并保存快照
  -> 可选 SiteRefreshed 发布边界
  -> 未读消息：写历史 -> 调用通知 Registry
  -> 分享率预警：写历史 -> 调用通知 Registry
```

每条通知独立写历史。带业务 `source` 的消息使用确定性事件键去重；无 `source` 的消息每次产生新历史。历史成功后才调用渠道，渠道错误只写不含凭证的警告日志。

## 关键决策

| 日期 | 决策 | 理由 |
| --- | --- | --- |
| 2026-08-16 | 接口定义在消费方，构造函数返回具体 `*Service` | 保持依赖显式且接口小于 5 个方法 |
| 2026-08-16 | 通知保持同步调用，不接 River | V2 在默认或允许发送时段内同步投递；River 会新增持久重试和崩溃恢复语义 |
| 2026-08-16 | 业务 `source` 同时写历史并传给渠道 | 严格保留 V2 将 SunnyPT 消息来源当作通知配置名筛选的既有行为 |
| 2026-08-16 | 发布器允许为空 | 当前插件和工作流运行时尚未移植，V2 没有其他核心 `SiteRefreshed` 订阅者 |
| 2026-08-16 | 分享率和 VIP 判断保持原正则 | 不在重写期间修复 V2 边界或文案 |

## 已知限制

- 当前发布器只接受整数站点 ID；批量刷新结束事件的 `site_id: "*"` 要在原版批量刷新/工作流能力移植时一并扩展。
- 当前未实现 V2 `NotificationSendTime` 的进程内延时队列；不能用 River 替代。
- `NoticeMessage` 和 `SiteRefreshed` 的监听者来自尚未移植的插件或工作流，因此生产装配暂不启用发布器。
- Haidan 的 V2 用户数据依赖外置 schema，当前没有可证明的解析器；该站点沿用无解析器时返回空成功的 V2 路径。

## 安全边界

- 本包不接收 HTTP 原始输入，也不保存站点凭证。
- 通知历史由参数化 PostgreSQL 实现持久化；本包不拼接 SQL。
- 渠道错误不回传底层文本，日志不包含 token、Cookie 或消息载荷。
- 所有阻塞操作沿用调用方 `context.Context`，不创建无生命周期 goroutine。
